# GitHub issues (duckspec)

When filing an issue against duckspec / duckboard, write only the essence of the request —
one short want statement, not an AI research dump.

## Rule

State the desire in a sentence or two. Optional: one line of why it matters *to you*.

Do **not** include:

- Architecture tables, current-behavior inventories, or “relevant caps / code” tours
- Speculative design options unless the human asked for a design discussion
- Long non-goals / ask sections that restate the product’s job for the maintainer

The maintainer already knows the product. The issue is a signal, not a brief.

## Shape

```markdown
# <short title — the want>

I want <concrete behavior>.

<optional one-line personal why>
```

## Counter-example

A full page of survival-layer tables and “possible directions” for what should have been:

> I want to switch projects or close the app and keep my sessions alive.
